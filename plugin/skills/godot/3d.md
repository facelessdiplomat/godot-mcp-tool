# 3D in Godot 4

## Axes, units and transforms

- +X is right, +Y is up, -Z is forward: a node faces along `-global_basis.z`. One unit is one meter, and gravity is
  9.8 m/s² (`physics/3d/default_gravity`); bodies read it with `get_gravity()`.
- `position` is relative to the parent and `global_position` to the world; a `Node3D` under a plain `Node` has the two
  equal. `rotation` is in radians, `rotation_degrees` in degrees. `look_at(target, Vector3.UP)` turns -Z towards a
  point; `rotate_y(angle)` turns around the up axis.
- Rough sizes: a person is 1.8 m tall, a door 1 m wide and 2.1 m tall; a `CapsuleShape3D` is 0.5 m in radius and 2 m
  tall by default.

## A character that walks and jumps

```gdscript
extends CharacterBody3D

const SPEED := 5.0
const JUMP_VELOCITY := 4.5


func _physics_process(delta: float) -> void:
	if not is_on_floor():
		velocity += get_gravity() * delta
	if Input.is_action_just_pressed("jump") and is_on_floor():
		velocity.y = JUMP_VELOCITY
	var input_direction := Input.get_vector("move_left", "move_right", "move_forward", "move_back")
	var direction := (transform.basis * Vector3(input_direction.x, 0, input_direction.y)).normalized()
	if direction:
		velocity.x = direction.x * SPEED
		velocity.z = direction.z * SPEED
	else:
		velocity.x = move_toward(velocity.x, 0, SPEED)
		velocity.z = move_toward(velocity.z, 0, SPEED)
	move_and_slide()
```

- The actions must exist: create them with `input_map_set`, such as `{"actions": {"move_forward": ["W"],
  "move_back": ["S"], "move_left": ["A"], "move_right": ["D"], "jump": ["Space"]}}`.
- `is_on_floor()` is valid after `move_and_slide()`. A jump velocity of 4.5 reaches about 1 m at default gravity.
- Movement relative to a camera: build `direction` with `camera.global_basis` instead of `transform.basis`, then set
  `direction.y = 0` and normalize it, so that a camera looking down does not slow the character.
- Check movement in the running game with one `game_input` that ends with a `read` step, such as
  `[{"action": "jump", "physics_frames": 1}, {"wait_physics_frames": 15}, {"read": "Player", "names": ["position",
  "is_on_floor()"]}]`; a jump is over before a later call can read it.

## Cameras

- A follow camera: a `Camera3D` as a child of the player, raised and pulled back, such as position `[0, 2, 5]` and
  `rotation_degrees` `[-15, 0, 0]`.
- A third-person rig: `Node3D` pivot → `SpringArm3D` (keeps the camera out of walls) → `Camera3D`. Mouse look: set
  `Input.mouse_mode = Input.MOUSE_MODE_CAPTURED` and turn the pivot by `InputEventMouseMotion.relative` in
  `_unhandled_input`.
- A viewport shows one camera: the first `Camera3D` that enters the tree, unless another one has `current = true`.

## Bodies and collisions

- `StaticBody3D` for level geometry, `RigidBody3D` for objects that physics moves (`apply_central_impulse`),
  `CharacterBody3D` for players and characters that code moves, `Area3D` for triggers (`body_entered(body)`).
- Every body and area needs a `CollisionShape3D` child with a shape: `BoxShape3D`, `CapsuleShape3D`, `SphereShape3D`.
- For quick level blockouts, CSG nodes (`CSGBox3D`, `CSGCylinder3D`, `CSGCombiner3D`) with `use_collision: true`
  give geometry and collision in one node.
- `collision_layer` is what a body is, `collision_mask` what it detects; the node tools take layer numbers, such as
  `[1, 3]`.

## Navigation

- An enemy finds its way with a `NavigationRegion3D` whose `NavigationMesh` covers the floor and the obstacles, which
  are children of the region by default, and a `NavigationAgent3D` on the enemy. Bake with `navigation_bake` after
  every change to the level; it reports the covered area or why it found none.
- The agent size lives in the `NavigationMesh`: `agent_radius` and `agent_height` should match the enemy's capsule.

```gdscript
extends CharacterBody3D

const SPEED := 4.0

@onready var agent: NavigationAgent3D = $Agent
@onready var player: Node3D = get_node("../Player")


func _physics_process(delta: float) -> void:
	if not is_on_floor():
		velocity += get_gravity() * delta
	agent.target_position = player.global_position
	var direction := Vector3.ZERO
	if not agent.is_navigation_finished():
		direction = global_position.direction_to(agent.get_next_path_position())
	direction.y = 0.0
	direction = direction.normalized()
	velocity.x = direction.x * SPEED
	velocity.z = direction.z * SPEED
	move_and_slide()
```

## Animation

- Doors, platforms and other scripted motion: an `AnimationPlayer` next to the moving nodes and `animation_set` with
  one track per property, such as `Door:position` with keys at 0 s and 1 s; paths start at the player's parent.
- An animation plays when the player's `autoplay` names it or a script calls `$AnimationPlayer.play("open")`; check
  it in the running game with `game_wait`, such as `position.y > 4.4` on `Door`.
- Characters that switch between animations: an `AnimationTree` set up with `animation_tree_set` as a state machine,
  Start leading to `idle` and transitions on conditions such as `moving`, which the script sets with
  `$AnimationTree.set("parameters/conditions/moving", velocity.length() > 0.1)`.
- Blends start from the `RESET` animation: a property that only some states animate takes its `RESET` value in the
  others. `animation_set` keys the current values there, as the editor does, so set up animations while the nodes
  are in their rest pose.

## Meshes, materials and light

- `MeshInstance3D` with a primitive mesh (`BoxMesh`, `CapsuleMesh`, `SphereMesh`, `PlaneMesh`) for placeholders;
  `StandardMaterial3D` for color (`albedo_color`), `roughness` and `metallic`. Share one material between nodes by
  saving it with `resource_create` and assigning its `res://` path.
- Light every scene: a `DirectionalLight3D` as the sun (`rotation_degrees` such as `[-50, 30, 0]`,
  `shadow_enabled: true`) and a `WorldEnvironment` whose `Environment` has `background_mode: "Sky"` and a `Sky` with a
  `ProceduralSkyMaterial`.
- Imported models arrive at any scale and orientation: read their size with `asset_import_settings_get` (a character
  180 units tall is in centimeters), fix it with `nodes/root_scale` in `asset_import_settings_set`, and check
  placed instances with `node_get_bounds`.
- Generated collision of an import (`generate/physics`) makes a `StaticBody3D`: right for props and level pieces, wrong
  for a model inside a `CharacterBody3D`, which then gets stuck on its own static body. Give the character body its
  own `CollisionShape3D` instead.

## Checking a 3D scene

- Numbers first: `node_get_bounds` answers "does the crate rest on the floor" (the bottom of its box against the top
  of the floor's) and "is the door wide enough for the player".
- Then pictures: `editor_screenshot` or `game_screenshot` with `views` from several angles, such as
  `["front", "top", "iso"]`, or framed on one node with `{"preset": "iso", "target": "Player"}`.
